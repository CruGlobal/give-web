# Localization — Focus Areas

This agent checks that text donors read is translated and that English and Spanish stay in step.
give-web uses angular-translate. All strings live in `src/common/app.config.js` in two blocks,
`$translateProvider.translations('en', {...})` and `$translateProvider.translations('es', {...})`,
with `preferredLanguage('en')`. Spanish is turned on only by branded checkout's `language`
attribute (`$translate.use(this.language || 'en')` in `branded-checkout.component.js`). So any
shared component that branded checkout renders (productConfig, contactInfo, addressForm,
paymentMethods, Recaptcha, thankYouSummary, checkout-error-messages) must be translated.

**Keys in both locales**

- Every key added to `en` must be added to `es` in the same PR, with the same name and the same
  `{{placeholders}}`. Keys are SCREAMING_SNAKE_CASE, grouped near related keys
- Today `es` has one key `en` lacks (`SPOUSE_NAME`), and about 80 `es` values are still English
  text. New keys should get real Spanish. If a translation isn't ready, the PR should say so
  rather than copy English silently
- Look for: a key used in a template or `$translate.instant` that is in neither block (it renders
  as the raw key); a key added to one block only; a renamed key left in the other; placeholder
  names that differ between locales

**User-visible strings**

- Template idiom: `<span translate>{{'KEY'}}</span>` or `<h4 translate>{{'KEY'}}</h4>`. With
  values: `translate-values="{amount: ($ctrl.premiumMinimum | giftAmount)}"`. With markup that
  needs Angular behavior: add `translate-compile` (used for `LOADING_ERROR`'s `ng-click`)
- In JS: `this.$translate.instant('KEY', values)` or `this.$translate([...keys]).then(...)`
  (`signUpModal.component.js`). In React: `$translate.instant(buttonLabel)` passed in through
  `react2angular` (`Recaptcha.tsx`)
- Look for: new hard-coded English in a template or controller that branded checkout can render.
  `coverFees.tpl.html` is an existing example ("card processing fees, please adjust my gift
  amount to"), so don't add more. Also look for English in `aria-label`, `placeholder`, `title`,
  and `alt` attributes, and in strings built in JS (`giftDates.quarterlyMonths` appends `'and '`)

**Translated error messages**

- Error banners map server errors to keys: `checkout-error-messages.tpl.html` switches
  `submissionError` to `REVIEW_*_ERROR` keys and falls back to `REVIEW_DEFAULT_ERROR`. Load
  errors use `LOADING_ERROR`, `LOADING_ERROR_RETRY`, `ADDING_CART_ERROR`, `FREQUENCY_ERROR`
- Showing `structuredErrorService.getErrorText(error)` or `getServerErrorMessage(error)` directly
  shows English server text. Prefer a translated key per known error `id` or exception name,
  with the server text as a fallback only
- Form validation messages are keys inside `ng-message` blocks (`AMOUNT_MIN_ERROR`,
  `AMOUNT_MAX_ERROR`, `VALID_DOLLAR_AMOUNT_ERROR`, `CARD_NUM_FULL`, ...)
- Look for: a new `ng-switch-when` without a matching key in both locales; a new exception name
  handled in `orderService` but missing from the switch

**Dates, numbers, and markup**

- `MomentLocalesPlugin` strips every moment locale but `en`, so `moment().format('MMMM')` is
  always English. Month names shown in Spanish need translation keys, or the PR must accept
  English
- Currency uses angular's `currency` filter and `giftAmount` (US format with `$`). That is
  intended for both locales
- Translation values may contain HTML (`<a href="mailto:eGift@cru.org">`). The
  `sanitizeParameters` strategy only cleans interpolated values. Never put donor or API text in a
  translation string. Pass it as a parameter
- `translate-values` that call controller methods (`{loadData: '$ctrl.initCart()'}`) must name a
  method that exists on that controller. Angular's `$parse` silently does nothing otherwise

**Checklist**

- [ ] Every new or changed user-visible string is a translation key
- [ ] Keys added, renamed, or removed in both `en` and `es`, with matching placeholders
- [ ] Spanish text is real Spanish, or the PR says it's pending
- [ ] Error messages that donors see are mapped to keys, with server text only as a fallback
- [ ] No donor or API text inside translation strings

## Mined from PR history

  key in the same diff, with real Spanish (not the English copied over) and the same casing
  (Title Case stays Title Case)
